# data/samples 样例数据说明

数据格式依据《数据契约 V1.3》（docs/data-contract.md）。所有 CSV 为 UTF-8（带 BOM）编码。

## benchmark/ 基准例（窄表对拍锚点，数字不得改动）
- generator_bids.csv：G1 150元/100MWh、G2 200元/100MWh（旧窄表格式，无 period 列）
- consumer_bids.csv：U1 300元/80MWh、U2 250元/60MWh
- 预期结果：出清价 200 元/MWh，成交 140 MWh，双方结算合计 56000 元
- 用途：B 的算法、C 的界面跑此数据必须得出上述结果（对拍验证）；平台"一键演示模式"内置案例
- V1.3 兼容导入：窄表导入时自动展开为 96 个时段同量同价（等价于旧引擎"每时段恒量"），
  新旧引擎逐时段出清结果应完全一致——这是 #67 重构的回归测试锚点

## scenario/ 典型场景（默认导入数据集，长表格式 V1.3）
- 双侧均为**逐时段长表**：行 = period 1–96 × 主体，列 = 第 N 段出力/报价成对展开
- generator_bids.csv：5 台常规机组（金陵电厂 #1/#2、龙潭电厂 #1/#2/#3），无 W/S 行、无机组类型列
  - 基荷段全天恒量：G1s1 150元/150MW、G2s1 170元/120MW、G1s2 180元/90MW、G3s1 190元/100MW（合计 460 MW）
  - 调峰段随负荷爬坡：G2s2 210元、G1s3 220元、G4s1 230元、G3s2 240元、G5s1 260元（按 residual 递次启用）
- consumer_bids.csv：3 用户单段申报（L1 工业园 500元、L2 商业综合体 380元、L3 居民小区 280元），
  基准量之和 = 平均负荷 894.9 MW（按负荷曲线一键预填口径，逐时段 Σ申报量 = 负荷(t)）
- **默认预填态（渗透率 20%）逐时段供需恰好平衡**：火电申报(t) = Σ购电申报(t) − 20%×负荷(t)
- 预期出清价（MCP）：夜谷 210 → 早爬坡 220/230/240 → 早峰 260 → 午间 220 → 晚峰 260 → 夜间回落；
  全天 210–260 元五级阶梯，均价约 229.7 元，96 时段需求全额成交
- 生成脚本：gen_scenario_v13.py（可回溯每格数字的生成规则；改曲线/机组参数后重跑即可）

## curves/ 曲线数据（场景输入，V1.3 四角色）
- load_curve.csv：日负荷双驼峰 96 点（凌晨低谷 688 MW，早高峰约 1090 MW，晚高峰 1135.8 MW）
- renewable_output.csv：W1/W2 风电、S1 光伏形状曲线（0–1 归一口径见契约 §五）
- V1.3 角色：① 购电宽表一键预填模板；② 平衡校验锚点；③ 渗透率换算基准（P_re(t)=渗透率×负荷(t)）；
  ④ 展示对照线。**不直接进入撮合**
