# data/samples 样例数据说明

数据格式依据《数据契约 V1.0》（docs/）。所有 CSV 为 UTF-8 编码。
（2026-09-02 起：负荷概念退场，平台导入仅发电/购电两张申报表；新能源出力由仿真控制页滑块直给 MW。）

## benchmark/ 基准例（对拍锚点，数字不得改动）
- generator_bids.csv：G1 150元/100MWh、G2 200元/100MWh
- consumer_bids.csv：U1 300元/80MWh、U2 250元/60MWh
- 预期结果：出清价 200 元/MWh，成交 140 MWh，双方结算合计 56000 元
- 用途：B 的算法、C 的界面跑此数据必须得出上述结果（对拍验证）；平台“一键演示模式”内置案例

## scenario/ 典型场景（默认导入数据集，8 机组 + 3 用户）
- generator_bids.csv：5 火电（G1~G5 分价递增）+ 2 风电 + 1 光伏，合计申报 710 MWh
  - 风电/光伏申报段仅供申报展示，不参与撮合（新能源由 P2 滑块直给 RENEW 0 价段）
- consumer_bids.csv：3 用户（U1 500 元/200、U2 380 元/250、U3 280 元/200），合计 650 MWh
  - 每时段需求 = 购电申报总量（恒定）；650 = 火电申报 590 + 默认滑块 60，默认状态供需平衡
  - 用户报价均高于火电最高报价 260 元，保证火电全时段可成交
- 预期效果：滑块 0→200 MW 时，新能源消纳 0→200，边际机组由 G5(260) 降至 G4(230)，饼图占比与电价同步变化
