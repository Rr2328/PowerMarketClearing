## 决策登记（2026-08-31 定稿 · D7 于 2026-09-02 补充）

| --- | --- | --- |

| D2 | **删除「只报量」模式** | 平台只保留「报量报价」一种需求组织方式；负荷曲线不再作为刚性垂直需求线进入撮合；相应基准对拍口径只保留双侧一条。 |

| D5 | **负荷曲线角色重定义** | 只报量删除后，负荷曲线承担四职责：① 购电长表「一键预填」模板；② 平衡校验锚点；③ 渗透率换算分母；④ 展示对照线。**不直接进 ClearMarket**。 |
| D6 | **样例数据随 #67 重标定** | 现样例发电合计 590 MW、购电合计 650 MW，盖不住负荷曲线 688–1136 MW；重标定目标：双侧申报覆盖典型日负荷，默认预填状态下逐时段基本平衡。 |

## 一、总则（相对 V1.1 的增改）

1. **两类数据**不变：
   | 类型 | 内容 | 特点 |
   | --- | --- | --- |
   | 段申报（长表） | 发电申报表、购电申报表 | 行 = `period(1–96)`；列 = 该时段各申报段的出力(MW)+报价(元/MWh)；同一机组 96 行 |
   | 时段曲线 | 负荷曲线、新能源出力 | 96 点场景文件（预测输入），**非申报**，不参与报价 |

   出清时，每个时段取申报长表的**第 t 周期行**与场景曲线，交叉一次（V1.1 的"按负荷等比缩放"口径删除，见 D1）。

2. **申报量语义（教学约定，沿旧）**：申报量单位为 MW（示例口径），表示**该时段可用于出清的功率**；撮合按数值直接相加、**不乘时段时长**。负荷曲线与出力曲线按 MW 存，参与比较时数值口径一致（引擎对 MW 不做时长换算，全程用数值直接撮合）。
3. **兼容导入（旧窄表 → 长表自动展开）**，分三步：
   - **识别**：DataReader 读表头，**无 `period` 列** → 判定为旧窄表（V1.1 格式：一行 = 主体×段，含电价与申报量）；
   - **展开**：先按机组把多条段行**合并成对列**（段1量/价、段2量/价…），再**复制 96 份**（period 1–96），每份量、价完全相同——即"每个时段申报完全一样"；旧文件的「机组类型」列忽略不校验（D7）；
   - **展开后不锁死**：96 行只是初始值，导入后任意时段仍可单独编辑（想模拟"前 48 时段老报价、后 48 时段改价"就直接改后一半）。

   示例——旧窄表：

   ```csv
   机组ID,机组名称,机组类型,申报段,电价(元/MWh),申报量(MW)
   G1,一号火电,火电,1,150.0,100.0
   G1,一号火电,火电,2,180.0,60.0
   G2,二号火电,火电,1,170.0,80.0
   ```

   导入后自动展开为（96 个时段全部相同，此处截断）：

   ```csv
   period,电厂名称,机组编号,第1段出力(MW),第1段报价(元/MWh),第2段出力(MW),第2段报价(元/MWh)
   1,一号火电,G1,100.0,150.0,60.0,180.0
   1,二号火电,G2,80.0,170.0,,
   2,一号火电,G1,100.0,150.0,60.0,180.0
   2,二号火电,G2,80.0,170.0,,
   …
   96,一号火电,G1,100.0,150.0,60.0,180.0
   96,二号火电,G2,80.0,170.0,,
   ```

   **为什么值得留**：旧引擎 `clearPeriods` 本来就是"每个时段塞同一组数据"跑 96 遍；展开后的长表喂给新引擎，逐时段出清结果应与旧引擎**完全一致**——这就是新旧对拍的锚点。因此基准例文件**不改格式**，窄表原样存档、导入即展开。
4. **校验规则**沿用并适配长表：
   - ① 每主体申报段数 ≤ 5（不变）；
   - ② 段价单调：对每一行（每个 period），发电低段→高段**单调不减**；购电低段→高段**单调不增**；
   - ③ 电力一位小数、电价三位小数；
   - ④ 电价 0–540 元/MWh（课程自定义限价，双侧统一）；
   - ⑤ 错误提示具体到 **period + 机组 + 段**（如 `period34 · G1 段2：申报量为负`）。
   - **新增 ⑥**：每段出力 ≥ 0；段列顺序固定、成对出现；允许 0（该时段该段不申报 / 停机）。
5. **文件约定**：UTF-8 CSV，长表第一行表头：`period,电厂名称,机组编号,第1段出力(MW),第1段报价(元/MWh),第2段出力(MW),第2段报价(元/MWh),…`；列名与顺序固定，段数由表头成对列数决定（最多 5 段 = 10 列）。

## 二、发电机组申报表 generator_bids.csv（长表）

**用途**：电厂提交的逐时段"报价单"。供给曲线的来源。

### 2.1 格式（示意，3 段，96 行以 `…` 截断）

```csv
period,电厂名称,机组编号,第1段出力(MW),第1段报价(元/MWh),第2段出力(MW),第2段报价(元/MWh),第3段出力(MW),第3段报价(元/MWh)
1,金陵电厂,#1机组,120,185,80,255,60,330
1,金陵电厂,#2机组,100,205,70,275,40,350
2,金陵电厂,#1机组,120,185,80,255,60,330
2,金陵电厂,#2机组,100,205,70,275,40,350
…
96,金陵电厂,#1机组,120,185,80,255,60,330
96,金陵电厂,#2机组,100,205,70,275,40,350
```

- `period` 列 = 第几个 15 分钟（1–96）。同一机组在 96 个时段各一行。
- W1/W2/S1 行**删除**（D4；新能源出力由渗透率 × 曲线生成，不再出现在申报表）。
- **「机组类型」列删除**（D7）：申报表全部为常规机组，撮合与 UI 不再区分燃料类型，供给阶梯图例按机组/段价配色；导入旧文件若仍含该列，DataReader 忽略不校验。
- 同一机组同一段跨时段可不同量、不同价 → 模拟**爬坡 / 启停 / 顶峰调峰 / 分时报价**：晚峰出力填大、凌晨填小；默认状态下平台提供"全时段复制"快捷编辑。

### 2.2 逐时段供给

period=t 的供给曲线 = 该周期所有机组各段按报价**升序**堆叠的阶梯（新能源 0 价 RENEW 段优先占位，口径不变）。

## 三、购电申报表 consumer_bids.csv（长表）

**用途**：购电侧（售电公司 / 批发用户）逐时段"询价单"。**需求曲线的唯一来源**（D2：不再有只报量模式）。

### 3.1 格式

```csv
period,用户名称,负荷编号,第1段申报量(MW),第1段报价(元/MWh),第2段申报量(MW),第2段报价(元/MWh),第3段申报量(MW),第3段报价(元/MWh)
1,一号工业园区,L1,200,500,150,420,100,350
1,二号商业综合体,L2,250,380,120,300,,,
1,三号居民小区,L3,200,280,,,,
…
96,一号工业园区,L1,180,500,140,420,90,350
96,二号商业综合体,L2,230,380,110,300,,,
96,三号居民小区,L3,210,280,,,,
```

- 列结构与 `generator_bids.csv` 对称：period 行 + 主体 + 段成对列；缺段留空即可。

### 3.2 需求形成与校验

1. **需求曲线**：period=t 的需求 = 该周期全部用户段按报价**从高到低**聚合的递减阶梯，与供给阶梯交叉出清（V1.1 §3.4 的"按负荷等比缩放"**删除**，用户自己决定每个时段买多少、出什么价）；
2. **一键预填（工具，非撮合输入）**：新建/导入长表时可选"按负荷曲线预填"：
   - 记用户 k 第 s 段的基准申报量 `q_{k,s}`（导入窄表时为其单段数值），预填 `q_{k,s}(t) = q_{k,s} × w(t)`；
   - `w(t) = 负荷(t) ÷ 平均负荷`（均值=1 → 平均申报量不变，与旧口径可比）；
   - 预填只缩放**每段申报量**，**报价保持各时段一致**（默认全时段复制），预填后**逐格可改**；
3. **平衡校验（保存/导入提示，不阻断）**：
   - 逐时段口径：对每个 t，`Σ用户申报量(t)` 与 `负荷(t)` 的偏差曲线在 P1 显示提示（偏差 = 该时段供需缺口预测）；
   - 总量口径：`ΣΣ 申报量` 与 `Σ 负荷曲线` 总量偏差提示；
   - 只提示讲解用，不强制相等（允许老师刻意做"供不应求/过剩"场景）。

## 五、新能源出力 renewable_output.csv 与渗透率（D4）

**文件格式不变**（机组ID/机组类型/时段/出力(MW)，每台机组 96 行）。它是**形状曲线**，不是出力直给。

1. 该时段风光基准总出力 `P_base(t) = Σ 各机组形状出力(t)`；
2. 该时段新能源实际总出力 `P_re(t) = 渗透率 × 负荷(t)`；
3. 各机组实际出力 `(t) = 形状出力(t) ÷ P_base(t) × P_re(t)`（`P_base(t)=0` 时该时段全为 0，如夜间光伏）。

- **渗透率滑块：0–100%，默认 20%**（V1.1 的 0–50% 更新）。滑块只给一个数，96 点出力全自动生成，**不进申报表、不逐时段手填**。高占比（>80%）不对应现实运行场景，仅供观察"全绿 → 电价归零、常规机组挤出"的极限演示，日常演示建议 20–60%；
- **为何参照负荷(t) 而非申报量(t)**（2026-09-02 确认）：① 行业口径——渗透率 = 新能源发电量 / 全社会用电量（负荷）；② 职责分离——申报量是学生可编辑的决策变量，若锚在申报量上，改一格购电申报会导致新能源出力连动，两个旋钮互相干扰；③ 预填平衡态下 Σ购电申报(t) ≈ 负荷(t)，两口径数值几乎一致；④ 刻意失衡场景中新能源应随负荷（场景）出力，供需缺口由申报单独体现——若锚申报量，缺口会被新能源"自动补偿"，混淆两个教学概念。极端时段申报需求 < P_re(t) 时，0 价 RENEW 先成交、多余部分不成交（隐含弃风弃光，可作进阶讨论）；
- 与旧「直给固定 MW」滑块的关系：旧口径 = 每时段同一个 MW（不随负荷变）；渗透率口径 = 每时段 MW 随负荷缩放（占比恒定）。两者以同一 0 价 `RENEW` 供给段进撮合，引擎处理路径不变；
- 新能源机组（W/S）只存在于本文件；`generator_bids.csv` 中不再出现（D4）。

## 六、仿真模式与对拍（D2/D3）

**平台只保留一种需求组织方式：报量报价（双侧长表）。** 控制维度收敛为：

| 维度（P2） | 取值 | 影响 |
| --- | --- | --- |
| 定价结算模式 | MCP / PAB | 结算口径，不影响出清价形成 |
| 时段颗粒度 | 96（显示可切 24） | **引擎只跑 96**；24 为聚合视图（§七） |

- **删除**：只报量模式、垂直刚性需求基准（原模式一锚点）；
- **基准对拍**：保留"双侧报量报价"单基准。旧窄表基准例文件不改，导入后复制为 96 行同量同价，引擎逐时段结果应与旧恒量结果一致——由 B 以等价性手算回填并登记（等值于旧 200 元 / 140 MWh 系列锚点的长表展开口径，数字以 B 回填为准）；
- **场景数据**：随 #67 重标定（D6），默认预填态逐时段基本平衡、可演示早/晚峰涨价与新能源压价。

## 七、出清结果接口（V1.2 不变 + 24 视图规则）

1. `EntityCleared / PeriodResult / ClearingResult` 三个结构**不变**；连续仿真 `periods` 长度为 96（基准例 1 个）。
2. **24 视图聚合（C 展示层，B 不产出）**：
   - `clearingPrice`：每 4 个相邻时段**算术平均**（仅视图，不代表"小时出清价"）；
   - `clearedMW / genFee / conFee`：每 4 点**求和**；
   - 明细（genDetails/conDetails）不聚合。
3. 引擎侧 `clearPeriods` 从"每时段塞恒定 demand/renew"改为"每时段取长表 period=t 行 + 渗透率出力"，签名变化属 #67 实施细节，另行登记。
