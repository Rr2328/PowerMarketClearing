> 电力现货市场出清仿真平台 · 全组共同遵守的数据格式约定
>
> - 起草：A（数据模块）
> - 状态：初稿 · 待 B/C 确认后冻结
> - 确认方式：群内回复无异议

## 一、总则

1. **适用范围**：本契约定义平台**全部输入数据**的格式，A（数据）、B（算法）、C（界面）三方共同遵守；任何字段增删改须全组同意并在第七章版本记录中登记。

2. **单位约定**：

   | 量 | 单位 | 精度 |
   |---|---|---|
   | 电价 | 元/MWh | 三位小数（如 150.000） |
   | 电力（功率） | MW | 一位小数 |
   | 电量 | MWh | 一位小数 |

3. **通用校验（申报校验五规则）**——数据保存/导入时逐条检查，**任一条不通过即拒绝保存**，并逐条给出可读的错误提示：

   | # | 规则 | 出处 |
   |---|---|---|
   | ① | 每台机组/用户的申报段数 **≤ 5 段** | 省间现货规则 4.2.3 条 |
   | ② | 申报电价单调：**机组从低段到高段单调不减**（先卖便宜的）；**用户从低段到高段单调不增**（先买便宜的） | 省间现货规则 4.2.3 条 |
   | ③ | 电力按 MW、电价按元/MWh 规定精度填写 | 交易平台字段规范 |
   | ④ | 电价必须在 **0 ~ 540 元/MWh** 区间内 | 中长期细则第 92 条 |
   | ⑤ | 校验不通过必须给出**具体到行、可读**的错误提示，不许笼统报错 | 本组工程约定 |

4. **文件约定**：所有数据文件均为 **UTF-8 编码的 CSV**（逗号分隔，第一行为表头，列名与顺序固定，不得增删空列）。Excel/WPS 制作后以「CSV UTF-8 (*.csv)」另存。

5. **时段约定**：一天 96 个时段，每 15 分钟一个（时段 1 = 00:00~00:15，……，时段 96 = 23:45~24:00）。出处：省间现货规则 4.1 条。

## 二、发电机组申报表 generator_bids.csv

**用途**：电厂开市前提交的"报价单"——每台机组声明"愿意以什么价格卖多少电"。是出清算法的核心输入。

### 2.1 格式

```csv
机组ID,机组名称,机组类型,申报段,申报电价(元/MWh),申报电量(MWh)
G1,一号火电,火电,1,150.000,100.0
G1,一号火电,火电,2,180.000,60.0
G2,二号火电,火电,1,200.000,100.0
W1,一号风电,风电,1,0.000,50.0
S1,一号光伏,光伏,1,0.000,30.0
```

### 2.2 字段说明

| 列名 | 含义 | 填法与规则 |
|---|---|---|
| `机组ID` | 机组唯一编号 | 字母+数字（火电 G1/G2…、风电 W1/W2…、光伏 S1/S2…、水电 H1…）；同一机组多行共用一个 ID |
| `机组名称` | 给人看的名字 | 如"一号火电"，界面显示用，不得重名 |
| `机组类型` | 能源类型 | 火电 / 水电 / 风电 / 光伏 四种之一；新能源机组出力另受 renewable_output 表控制 |
| `申报段` | 第几段报价 | 从 1 开始连续编号；每台机组最多 5 段（规则①） |
| `申报电价` | 该段电的卖价 | 元/MWh，三位小数；0~540 区间（规则④）；低段→高段单调不减（规则②） |
| `申报电量` | 该段愿意卖的电量 | MWh，大于 0 |

> **设计说明：新能源为何报 0 价**——风电、光伏没有燃料成本，真实市场中它们基本"报量不报价"（价格接受者），报 0 保证优先被买入——这是本平台能演示「新能源把出清电价压低」这一教学要点的前提。

## 三、用户申报表 consumer_bids.csv

**用途**：买电方（大用户）的"询价单"——"愿意以不高于多少的价格买多少电"。用于**手算基准例**（算法对拍锚点）与**供需双边撮合**演示场景。

### 3.1 格式

```csv
用户ID,用户名称,申报段,申报电价(元/MWh),申报电量(MWh)
U1,一号线缆厂,1,300.000,80.0
U2,二号钢厂,1,250.000,60.0
```

### 3.2 字段说明

| 列名 | 含义 | 填法与规则 |
|---|---|---|
| `用户ID / 用户名称` | 编号与名字 | U1、U2…；名称如"一号线缆厂" |
| `申报段` | 第几段询价 | 从 1 开始；最多 5 段（规则①） |
| `申报电价` | 该段愿意出的最高买价 | 元/MWh，三位小数；0~540 区间（规则④）；**低段→高段单调不增**（与机组相反，规则②） |
| `申报电量` | 该段想买的电量 | MWh，大于 0 |

> **与负荷曲线的分工（必读）**——用户申报表用于「单时段基准例 / 双边撮合」场景；**96 时段连续仿真时，需求侧简化为一条负荷曲线（第四章），不再逐用户申报**。这是教学仿真的简化约定：两种仿真模式各用各的需求侧数据，互不冲突。

## 四、负荷曲线 load_curve.csv

**用途**：一天 96 个时段、每个时段全社会用电功率。是 96 时段连续仿真（创新点③）的需求侧数据。数据形态须呈典型日「双驼峰」：凌晨低谷、早高峰（约 8 点）、午后小回落、晚高峰（约 19 点）。

### 4.1 格式

```csv
时段,时刻,负荷(MW)
1,00:15,820.0
2,00:30,790.0
3,00:45,765.0
……（共 96 行，第 96 行对应 24:00）……
96,24:00,700.0
```

### 4.2 字段说明

| 列名 | 含义 | 填法与规则 |
|---|---|---|
| `时段` | 第几个 15 分钟 | 1~96 连续编号，一行一个，不得缺号、不得重复 |
| `时刻` | 对应钟点（给人看） | 00:15 起步、24:00 收尾，每行递增 15 分钟 |
| `负荷` | 该时段全社会用电功率 | MW，一位小数，大于 0；整体呈双驼峰形态 |

96 时段出处：省间现货规则 4.1 条（一天 96 个 15 分钟时段）。

## 五、新能源出力 renewable_output.csv

**用途**：风电、光伏机组的分时段出力预测，是创新点①「新能源动态出力 + 24h 连续仿真」的数据基础。

### 5.1 格式

```csv
机组ID,机组类型,时段,出力(MW)
W1,风电,1,35.0
W1,风电,2,38.0
……（W1 共 96 行）……
S1,光伏,1,0.0
S1,光伏,2,0.0
……（夜间光伏全为 0，白天逐时段变化）……
S1,光伏,50,52.0
```

### 5.2 字段说明

| 列名 | 含义 | 填法与规则 |
|---|---|---|
| `机组ID / 机组类型` | 哪台新能源机组 | ID 必须与 generator_bids 中的 ID 一致（如 W1、S1）；类型只能填 风电 或 光伏 |
| `时段` | 第几个 15 分钟 | 1~96；**每台机组各占 96 行** |
| `出力` | 该时段实际发出的功率 | MW，一位小数；≥ 0 且 ≤ 该机组申报电量总和；光伏夜间为 0、午间（约 11~14 点）最大；风电整夜有波动 |

> **渗透率换算关系（B、C 必读）**——渗透率 = 新能源出力 ÷ 负荷，界面上是一个 0~50% 的滑条。滑条变动时，新能源出力整体按比例缩放：**实际出力 = 表中基准出力 × 渗透率系数**。因此本表存的是「基准出力形状」，供 B 的算法与 C 的界面按同一公式换算，两边算出的数必须一致。

## 六、文件与仿真场景对应关系

| 场景 | 需要的文件 | 说明 |
|---|---|---|
| **手算基准例**（对拍锚点） | generator_bids + consumer_bids（各 2 条记录） | 标准答案：出清价 200 元/MWh、成交 140 MWh、结算合计 56000 元；B 的算法、C 的界面跑此数据必须得出此结果 |
| **双边撮合演示**（PAB 模式） | generator_bids + consumer_bids | 按各自报价成交，用于演示 MCP / PAB 激励差异 |
| **96 时段连续仿真** | generator_bids + load_curve + renewable_output | 需求侧用负荷曲线；新能源按出力表动态变化；输出 96 时段出清价曲线（双驼峰） |

对拍锚点数据出处：《三人团队工作路径与实现方法说明》第 11 部分手算基准例（G1 150元/100MWh、G2 200元/100MWh、U1 300元/80MWh、U2 250元/60MWh）。
