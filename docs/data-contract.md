# 数据契约 V1.1

> 电力现货市场出清仿真平台 · 全组共同遵守的数据格式约定
>
> - 修订：V1.1 按「发用两侧报量报价 · 双边定价」机制全面改版（依据《平台说明文档》V1.1 与《双报双收机制修正方案》定稿结论）

## 一、总则

1. **适用范围**：本契约定义平台**全部输入数据**的格式，A（数据）、B（算法）、C（界面）三方共同遵守；任何字段增删改须全组同意并在第七章版本记录中登记。
2. **两类数据（先分清这个，很多问题就不会混）**：
   | 类型       | 内容          | 特点                               | 谁产生                  |
   | -------- | ----------- | -------------------------------- | -------------------- |
   | **段申报**  | 发电申报表、购电申报表 | 日内**不变**的「价格-电量」段曲线，市场主体填出来的市场行为 | 用户在 P1 编辑            |
   | **时段曲线** | 负荷曲线、新能源出力  | 96 点**预测输入**（物理场景），非申报、不参与报价     | 典型日预设 × 峰值 / 渗透率自动生成 |
   出清时，每个时段把「当前时段的场景（曲线）」和「日内不变的申报」放在一起交叉一次。
3. **单位约定**：
   | 量      | 单位    | 精度              |
   | ------ | ----- | --------------- |
   | 电价     | 元/MWh | 三位小数（如 150.000） |
   | 电力（功率） | MW    | 一位小数            |
   | 电量     | MWh   | 一位小数            |
4. **双侧申报校验五规则**——数据保存/导入时逐条检查，**任一条不通过即拒绝保存**，并逐条给出可读的错误提示（提示信息按「发电 · / 购电 ·」分侧标注）：
   | # | 规则                                                                       | 说明                                                          |
   | - | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
   | ① | 每台机组 / 购电申报的申报段数 **≤ 5 段**                                               | 双侧对称简化（参照省间现货规则 4.2.3 条发电侧口径）                               |
   | ② | 申报电价单调：**发电侧从低段到高段单调不减**（先卖便宜的）；**购电侧从低段到高段单调不增**（价格越高、愿意买的量越少，方向与发电侧相反） | 双侧对称简化                                                      |
   | ③ | 电力按 MW、电价按元/MWh 规定精度填写                                                   | 交易平台字段规范                                                    |
   | ④ | 电价必须在 **0 ~ 540 元/MWh** 区间内，**双侧统一适用**                                   | **课程自定义统一限价**（非某省真实值；真实省级限价多在 800~1500 元/MWh，答辩时如被问到以此口径说明） |
   | ⑤ | 校验不通过必须给出**具体到行、可读**的错误提示，不许笼统报错                                         | 本组工程约定                                                      |
5. **文件约定**：所有数据文件均为 **UTF-8 编码的 CSV**（逗号分隔，第一行为表头，列名与顺序固定，不得增删空列）。Excel/WPS 制作后以「CSV UTF-8 (*.csv)」另存。
6. **时段与颗粒度**：数据以 **96 时段为基准**（每 15 分钟一个，时段 1 = 00:0024:00；出处：省间现货规则 4.1 条）。**切换 24/96 颗粒度不改变已录入数据**：
   - 段申报与颗粒度无关（日内一份，96 个时段共用）；
   - 负荷 / 新能源以 96 点基准存储，选 24 时段时由系统**每 4 个相邻时段取平均**自动聚合，用户不需要也不允许手填 24 点版本。

## 二、发电机组申报表 generator_bids.csv

**用途**：电厂开市前提交的"报价单"——每台机组声明"愿意以什么价格卖多少电"。是供给曲线的来源、出清算法的核心输入。

### 2.1 格式

```csv
机组ID,机组名称,机组类型,申报段,申报电价(元/MWh),申报电量(MWh)
G1,一号火电,火电,1,150.000,100.0
G1,一号火电,火电,2,180.000,60.0
G2,二号火电,火电,1,200.000,100.0
W1,一号风电,风电,1,0.000,50.0
S1,一号光伏,光伏,1,0.000,30.0
```

### 2.2 字段说明

| 列名     | 含义       | 填法与规则                                                     |
| ------ | -------- | --------------------------------------------------------- |
| `机组ID` | 机组唯一编号   | 字母+数字（火电 G1/G2…、风电 W1/W2…、光伏 S1/S2…、水电 H1…）；同一机组多行共用一个 ID |
| `机组名称` | 给人看的名字   | 如"一号火电"，界面显示用，不得重名                                        |
| `机组类型` | 能源类型     | 火电 / 水电 / 风电 / 光伏 四种之一；新能源机组出力另受 renewable_output 表控制     |
| `申报段`  | 第几段报价    | 从 1 开始连续编号；每台机组最多 5 段（规则①）                                |
| `申报电价` | 该段电的卖价   | 元/MWh，三位小数；0~540 区间（规则④）；低段→高段单调不减（规则②）                   |
| `申报电量` | 该段愿意卖的电量 | MWh，大于 0                                                  |

> **设计说明：新能源为何报 0 价**——风电、光伏没有燃料成本，真实市场中它们基本"报量不报价"（价格接受者），报 0 保证优先被买入——这是平台能演示「新能源把出清电价压低」这一教学要点的前提。

> **供给曲线形成（B 实现口径）**——各机组申报段按电价从低到高堆叠成阶梯形供给曲线；新能源实际出力（按第五章渗透率换算）以零边际成本**优先占位**，常规机组申报竞争剩余的净负荷。

## 三、购电申报表 consumer_bids.csv

**用途**：购电侧（售电公司 / 批发用户，教学简化为聚合申报）的"询价单"——"愿意以不高于多少的价格买多少电"。是**需求曲线的来源**，与发电申报对等，是平台的正式输入（不再只是演示场景）。

### 3.1 购电申报模式（P2 仿真控制参数，不属于本 CSV）

| 模式             | 需求曲线形态                                    | 本表是否参与                 |
| -------------- | ----------------------------------------- | ---------------------- |
| **报量报价**       | 各用户申报聚合成的**递减阶梯**（价格越高买得越少），与供给曲线交叉出清     | **参与**：价格列与电量列都读       |
| **只报量**（报量不报价） | 该时段负荷处的**垂直刚性线**（相当于按限价上限申报），出清价由供给曲线单独决定 | **不参与**：价格列忽略，需求量直接取负荷 |

> 两种模式共用同一份数据文件；切换模式是 P2 的仿真参数，不改动任何 CSV。

### 3.2 格式

```csv
用户ID,用户名称,申报段,申报电价(元/MWh),申报电量(MWh)
U1,一号线缆厂,1,300.000,80.0
U2,二号钢厂,1,250.000,60.0
```

### 3.3 字段说明

| 列名            | 含义         | 填法与规则                                                |
| ------------- | ---------- | ---------------------------------------------------- |
| `用户ID / 用户名称` | 编号与名字      | U1、U2…；名称如"一号线缆厂"                                    |
| `申报段`         | 第几段询价      | 从 1 开始；每用户最多 5 段（规则①）                                |
| `申报电价`        | 该段愿意出的最高买价 | 元/MWh，三位小数；0~540 区间（规则④）；**低段→高段单调不增**（与发电侧方向相反，规则②） |
| `申报电量`        | 该段想买的电量    | MWh，大于 0                                             |

### 3.4 聚合与逐时段缩放（B、C 必读）

1. **聚合**：B 将所有用户的申报段按电价**从高到低**合并排序，聚合成一条递减的需求阶梯曲线（教学简化：不逐用户撮合，只保留聚合曲线）；
2. **总量校验**：购电申报总电量（Σ 各段电量）= 当日负荷总电量（Σ 时段负荷 × 时段时长）。不满足时 P1 保存校验报错，提示差额；
3. **逐时段缩放**：购电申报是日内不变的"形状"，各时段的需求曲线按该时段负荷等比缩放——该时段第 k 段电量 = 申报第 k 段电量 × (该时段负荷 ÷ 当日负荷总量)。这样每个时段都同时满足"总量 = 负荷"和"价格分布形状不变"。

## 四、负荷曲线 load_curve.csv

**用途**：一天 96 个时段、每个时段全社会用电功率。**定位：刚性预测输入（非申报）**——由典型日预设模板（双驼峰形状系数）× 峰值数值自动生成，仿真中不随申报、出清、价格变化；它决定"这一天要用多少电"这个物理底线。

### 4.1 格式

```csv
时段,时刻,负荷(MW)
1,00:15,820.0
2,00:30,790.0
3,00:45,765.0
……（共 96 行，第 96 行对应 24:00）……
96,24:00,700.0
```

### 4.2 字段说明

| 列名   | 含义         | 填法与规则                                          |
| ---- | ---------- | ---------------------------------------------- |
| `时段` | 第几个 15 分钟  | 1~96 连续编号，一行一个，不得缺号、不得重复                       |
| `时刻` | 对应钟点（给人看）  | 00:15 起步、24:00 收尾，每行递增 15 分钟                   |
| `负荷` | 该时段全社会用电功率 | MW，一位小数，大于 0；整体呈双驼峰形态（凌晨低谷、早高峰约 8 点、晚高峰约 19 点） |

> **生成与存储约定**——A 提供的预设模板为 96 点**形状系数**（0~1），界面填峰值（MW）后按 `形状系数 × 峰值` 展开成 96 点负荷曲线。存储只存 96 点基准；24 时段由系统聚合（总则第 6 条），不存在 24 点版本的文件。

## 五、新能源出力 renewable_output.csv

**用途**：风电、光伏机组的**基准出力形状**（分时段）。实际出力不直接用表中的值，而是由 P2 的**渗透率滑块（0~50%，默认 20%）**&#x7EDF;一换算。

### 5.1 格式

```csv
机组ID,机组类型,时段,出力(MW)
W1,风电,1,35.0
W1,风电,2,38.0
……（W1 共 96 行）……
S1,光伏,1,0.0
S1,光伏,2,0.0
……（夜间光伏全为 0，白天逐时段变化）……
S1,光伏,50,52.0
```

### 5.2 字段说明

| 列名            | 含义             | 填法与规则                                                 |
| ------------- | -------------- | ----------------------------------------------------- |
| `机组ID / 机组类型` | 哪台新能源机组        | ID 必须与 generator_bids 中的 ID 一致（如 W1、S1）；类型只能填 风电 或 光伏 |
| `时段`          | 第几个 15 分钟      | 1~96；**每台机组各占 96 行**                                  |
| `出力`          | 该时段的**基准形状**出力 | MW，一位小数；≥ 0；光伏夜间为 0、午间（约 11~14 点）最大；风电整夜有波动           |

### 5.3 渗透率换算公式（B、C 必须用同一式）

**定义：渗透率 = 新能源出力 ÷ 负荷（瞬时出力占比）**。滑块变动时按下列步骤换算，保留风光各自的形状特征：

1. 该时段风光基准总出力 `P_base(t) = Σ 表中各机组出力(t)`；
2. 该时段新能源实际总出力 `P_re(t) = 渗透率 × 负荷(t)`；
3. 各机组实际出力 `(t) = 表中该机组出力(t) ÷ P_base(t) × P_re(t)`（该时段 `P_base(t) = 0` 时，各机组出力均为 0）。

B 的算法与 C 的界面（曲线预览）都必须按此式计算——**两边算出的数必须一致**，否则联调时对不上。

## 六、仿真模式与文件对应关系

三个控制维度**相互正交**，任意组合：

| 维度（P2 设置） | 取值                          | 影响                          |
| --------- | --------------------------- | --------------------------- |
| 购电申报模式    | 报量报价 / 只报量                  | 需求曲线形态（递减阶梯 / 垂直刚性线），见第三章   |
| 定价结算模式    | MCP（统一出清价）/ PAB（发电侧按各自报价结算） | 结算口径，不影响出清价格的形成             |
| 时段颗粒度     | 24 / 96                     | 计算与展示粒度（96 点基准自动聚合），不影响数据文件 |

| 场景              | 需要的文件                                          | 说明                             |
| --------------- | ---------------------------------------------- | ------------------------------ |
| **模式一：只报量仿真**   | generator_bids + load_curve + renewable_output | 需求 = 负荷垂直线，出清价由供给侧（含新能源优先出力）决定 |
| **模式二：报量报价仿真**  | 上述全部 + consumer_bids                           | 需求 = 购电申报聚合递减阶梯，供需交叉出清         |
| **双基准对拍（验收锚点）** | 模式一基准例 + 模式二基准例                                | 见下                             |

**双基准对拍（附录 D 口径）**：

- **模式一基准（刚性需求）**：沿用原手算基准例，数值**不变**——出清价 200 元/MWh、成交 140 MWh、结算合计 56,000 元；需求总量 140 MWh 即原基准例购电侧总量（U1 80 + U2 60）。B 的算法、C 的界面跑此数据必须得出此结果；
- **模式二基准（弹性需求）**：购电侧按 3 段递减报价设计，供需交叉点落中价段——**由 B 按双侧口径新设计并手算标定**，定稿后回填本契约；
- 答辩口径：同一基准例在两种申报模式下分别对拍，验证平台正确还原「刚性需求」与「弹性需求」两种市场组织方式。

模式一基准数据出处：《三人团队工作路径与实现方法说明》第 11 部分手算基准例（G1 150元/100MWh、G2 200元/100MWh、U1 300元/80MWh、U2 250元/60MWh）。
