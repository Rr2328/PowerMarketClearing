# 样例数据现实性对照说明

> 目的：对照真实省级电力现货市场（限价体系、价格水平、负荷形态、机组参数），逐项检查现有样例数据是否"奇怪"，并给出贴近现实的调整建议。
> 范围：`data/samples/` 下全部样例（scenario / scenario_balanced / curves / benchmark）+ UC 元数据 + 二次曲线参数 + 限价常量（540）。
> 日期：2026-09-13。所有外部数据均标注来源，文末附来源清单。

## 0. 先回答核心问题：540 上限低不低？

**低，而且低得有明确量级——但要先分清它扮演的角色。**

现实中省级现货市场的价格上限（出清限价）主流区间确实是 **1200–1500 元/MWh**：

| 省/区域 | 申报限价（元/MWh） | 出清限价（元/MWh） |
|---|---|---|
| 山西 | 0–1500 | 0–1500（有二次限价） |
| 江苏 | 0–1500 | 0–1500 |
| 广东 | -50–1800 | -50–1800 |
| 山东 | -80–1300 | -100–1500 |
| 上海 | 0–1500 | 0–1800（有二次限价） |
| 河北 | 0–1200 | 0–1200 |
| 辽宁 | -100–1100 | -100–1500 |
| 吉林 | 0–1200 | 0–1500 |
| 浙江 | -200–800 | -200–1200 |
| 安徽 | 0–800 | 0–800 |
| 湖南 | 0–900 | 0–900 |
| 甘肃 / 新疆 / 青海 | 40–650 左右 | 40–650 左右 |

（完整对照见文末来源 [1][2]）

我们的 **540** 在上表里只比甘肃/新疆/青海（650）还低一档，低于全国绝大多数省份。**如果把它当"出清限价"，确实偏低。**

但注意：在我们的代码里，540 实际上是 **失负荷松弛价 / λ 封顶价**（`uc_solver.cpp` 的 `kShedCost = 540`，V1.3.1 定价口径）。它的语义是"系统缺 1 MWh 电的社会代价"，而不是"市场规则允许的最高申报价"。这两个概念在现实市场里是分开的：

- 现实规则：申报限价 / 出清限价（上表）+ 失负荷价值 VOLL（各省通常取 **5–15 元/kWh，即 5000–15000 元/MWh** 量级，用于可靠性评估而非直接出清）；
- 我们的简化：把两者合一，540 同时充当限价和稀缺价。

**结论**：540 不算"错"，但作为教学数据确实不贴现实。建议整体上移（方案见 §4）。

### 🔍 "规模不对"要正面说明的

| 维度 | 我们 | 现实 | 定位建议 |
|---|---|---|---|
| **系统规模** | 峰值负荷 1136 MW ≈ **114 万 kW** | 你说的省级 800–1500 万 kW 属实（如江苏 2026 年 1 月最高负荷 1.35 亿 kW [4]） | 我们只相当于省级的 **1/7 – 1/13**。这不是数据错误，而是**教学场景定位**：5 台火电 + 3 台新能源 + 3 个用户，天然是"**地市级/园区级切片**"。建议：① 在 README/报告里明确定位为"地市级试点切片"；② 如果想要省级观感，可以加一个可选的"省级规模场景"（40–60 台机组、负荷 ×10），代码不用动，只加数据 |
| **机组单机容量** | 150–240 MW（15–24 万 kW 级煤机） | 现役主力煤机 30/60/100 万 kW | 单机偏小一档，但作为地市切片的机组成立 |
| **启动费/空载费** | 启动 2000–8000 元、空载 250–1200 元/h | 30 万 kW 煤机一次启动成本现实约**数十万元**；空载煤耗成本每小时数万元 | **低 1–2 个数量级**。教学上小数字好口算，是当初刻意简化；若追求贴现实可放大 10–20 倍，但会改变 UC 结果的直觉（开停机会明显变"贵"） |

## 3. 综合判断

1. **形态层面（曲线、粒度、报价格式、渗透率）——已经很现实**，负荷曲线峰谷特性甚至好于多数教学案例，不用动。
2. **价格层面（成本、报价、出清价、限价）——系统性偏低约 20–60%**，根子在一处：火电边际成本起点定低了，其余价格都是它的函数。改一处（成本/报价族）即可全链路贴现实。
3. **规模层面——不是错误，是定位**，补一句"地市级切片"的说明即可自洽；可选做省级场景。

## 4. 调整建议（若执行，按此清单）

### 方案 A：价格族整体校准（已定稿执行，2026-09-13）

| 项目 | 现值 | 定稿值 | 现实依据 |
|---|---|---|---|
| 失负荷价 / λ 封顶 `kShedCost` | 540 | **1500**（对齐主流省出清上限） | 来源 [1][2] |
| 火电边际成本（meta） | 150/170/190/230/260 | **270/290/320/370/410** | 燃料成本 237.5–310 元/MWh [3][6] + 留边际利润 |
| 发电分段报价（bids） | 150–240 基荷 + 210–260 调峰 | **基荷 270–320 + 调峰 330–410**（五级阶梯，由 gen_scenario_v13.py 重生成） | 同上 |
| 期望出清价带 | 210–260（均价 229.7） | **330–410 五级**（均价约 350） | 贴近山西 290 / 山东 325 / 安徽 360 [7] |
| 购电报价（3 用户） | 500/380/280 | **700/600/500** | 保持"用户 WTP ≫ 出清价"分层（均 > 410） |
| 二次曲线截距 b | 80 | **300**（a 保持 0.045，p=260 时 MC≈323） | 对齐煤机边际成本 |
| 启动费 / 空载费 | 2000–8000 / 250–1200 | **暂不动**（可选二期 ×10） | 教学口算友好；放大不改变机制演示 |
| benchmark/ 基准例 | 250 等固定锚点 | **保持不动** | 对拍锚点 + 测试基准，独立于场景价格族 |

**连锁影响（必须同步改，否则测试全红）**：
- `clearing_facade_test.cpp` 锚点用例：基准例 250/50/12500、MCP 阶梯 210–260、均价 229.7 相关断言全部重算；
- `uc_solver_test.cpp` ⑧ 用例：λ ≤ 540 的断言 → 1500；峰时 540 触发断言同步；
- `data/samples/gen_scenario_v13.py`：样例由脚本生成，改价后重跑即可回溯（这正是当初把它做成可回溯脚本的价值）；
- `docs/data-contract.md`：若文中引用了 540/价格数值，一并更新；
- P2 状态栏"稀缺出清价 540"的文案取自常量，改常量即自动跟随（需 grep 确认无硬编码 540）。

### 方案 B：省级规模场景（可选，二期）

新增 `data/samples/scenario_province/`：40–60 台机组（30/60 万 kW 级为主）、负荷 8000–15000 MW × 96 期、新能源占比 15–25%。**代码零改动**，只加数据文件 + 让生成脚本支持规模参数。优点：报告里可写"支持地市级与省级两种规模"；代价：MILP 规模变大（60×96 变量约 2 万+，HiGHS 求解秒级，无压力）。

### 不建议动的

- 负荷曲线形态（已贴现实）；
- 96 期粒度、长表契约结构（V1.3 已定稿）；
- 渗透率机制（参数默认 20% 合理）。
